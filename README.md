# 연강 이동 시간 점검

**다음 수업까지, 이동할 시간이 충분할까?**

여러 건물을 오가며 연속 수업을 듣는 대학생을 위한 정적 웹앱입니다. 수업 시간과 가상 건물을 등록하면 수업 사이의 이동 여유 시간을 계산하고, 부족하거나 겹치는 구간을 알려줍니다.

시간표만으로는 알기 어려운 “다음 건물까지 제시간에 도착할 수 있는가”를 한눈에 확인하도록 만들었습니다. 로그인, 백엔드, 데이터베이스, 외부 API 없이 동작합니다.

> 가상의 건물 및 예상 이동 시간입니다. 실제 대학 시스템, 건물, 거리와 무관합니다.

## 핵심 기능

- **정확히 세 화면**: 시간표 홈 / 수업 추가·수정 / 이동 점검 상세
- 월요일~금요일 시간표 분리 및 시작 시각 기준 자동 정렬
- 수업 추가·수정·삭제와 입력 검증, 삭제 전 확인
- 연속된 두 수업 사이 공백·예상 이동·실제 여유 시간 계산
- 선택한 요일에서 가장 빠듯한 구간 요약
- 이동 부족은 코랄색, 이동 가능 및 여유 0분은 파란색으로 표시
- 수업 시간 중복을 단순 이동 부족과 구분해 경고
- localStorage 자동 저장, 새로 고침 후 유지, 전체 삭제 후 빈 시간표 유지
- 잘못된 저장 데이터 및 저장 권한·용량 오류 처리
- 모바일 세로 시간표, PC의 시간표·요약 병렬 배치
- 키보드 탐색, 포커스 표시, 입력 오류 연결, 44px 이상 수정·삭제 버튼

## 사용 방법

1. 최초 실행하면 월요일 3개, 화요일 2개의 예시 수업이 표시됩니다.
2. 요일 버튼으로 해당 요일의 시간표를 선택합니다.
3. **수업 추가**를 눌러 수업명, 요일, 시작·종료 시각, 건물을 입력합니다.
4. 저장하면 해당 수업의 요일 홈으로 돌아가며 시간순으로 정렬합니다.
5. 수업 카드의 연필 버튼으로 수정하거나 휴지통 버튼으로 삭제합니다.
6. **이동 점검** 또는 **이동 점검 자세히 보기**에서 구간별 계산을 확인합니다.
7. 뒤로 가기 링크와 브라우저 뒤로 가기를 사용할 수 있습니다.

수업명은 공백을 제외한 내용이 필요하며 최대 40자입니다. 요일은 월~금, 건물은 A~D관만 선택할 수 있습니다. 종료 시각은 시작 시각보다 늦어야 하며 자정을 넘기는 수업은 등록하지 않습니다. 수업 간 중복은 등록을 막지 않고 분석 결과에서 경고합니다.

## 기술 스택

| 구분 | 사용 기술 |
|---|---|
| 화면 | HTML5, CSS3, Vanilla JavaScript ES6+ |
| 저장 | 브라우저 localStorage |
| 배포 대상 | GitHub Pages 정적 호스팅 |
| 검증 도구 | Node.js 기본 테스트 러너, Playwright, axe-core |

앱을 실행하는 데 npm 설치나 빌드가 필요하지 않습니다. npm 패키지는 개발 중 자동 테스트에만 사용하며 앱에서 로드하지 않습니다. 폰트, 아이콘, 지도 등도 외부 서버에 요청하지 않습니다.

## 실행 방법

### 바로 열기

폴더 구조를 유지한 채 `index.html`을 브라우저로 엽니다. 스크립트는 일반 `defer` 방식으로 읽어 ES 모듈의 로컬 파일 제한을 피했습니다. Chrome에서 직접 실행과 저장을 확인했습니다.

### 로컬 정적 서버

프로젝트 폴더에서 실행합니다. Python 3가 설치되어 있어야 합니다.

```sh
python3 -m http.server 4173 --bind 127.0.0.1
```

브라우저에서 `http://127.0.0.1:4173`을 엽니다. 이는 개발용 정적 파일 서버이며 앱에는 별도 백엔드가 없습니다.

저장 데이터는 브라우저와 출처별로 구분됩니다. 로컬 파일, 로컬 서버, 공개 배포 주소의 시간표는 서로 공유되지 않습니다. 브라우저의 사이트 데이터를 지우면 시간표도 지워집니다.

│   ├── storage.js             # 저장 스키마와 오류 처리
│   └── app.js                 # 화면 전환, CRUD, 렌더링
├── tests/
│   ├── logic.test.cjs         # 계산·저장 단위 테스트
│   └── browser.spec.cjs       # 실제 브라우저 기능·접근성 테스트

해시 경로로 세 화면을 전환하므로 GitHub Pages에 별도 라우팅 설정이 필요하지 않습니다. 추가와 수정은 같은 폼 화면을 사용합니다.

| 화면 | 경로 예시 |
|---|---|
| 홈 | `#home?day=mon` |
| 추가·수정 | `#class/new?day=mon`, `#class/sample-1?day=mon` |
| 상세 | `#check?day=mon` |

### 가상 이동 시간

| 건물 | A관 | B관 | C관 | D관 |
|---|---:|---:|---:|---:|
| A관 | 0 | 10 | 8 | 15 |
| B관 | 10 | 0 | 7 | 13 |
| C관 | 8 | 7 | 0 | 6 |
| D관 | 15 | 13 | 6 | 0 |

단위는 분이며 양방향 값이 같습니다. 단 실제 지도, 보행 속도, 교통 상황은 반영하지 않습니다.

### 계산

시간을 `시 × 60 + 분`으로 변환한 정수로 계산합니다. 같은 요일의 수업을 정렬한 뒤 **인접한 두 수업**을 분석합니다.

```text
공백 시간 = 다음 수업 시작 − 이전 수업 종료
실제 여유 시간 = 공백 시간 − 건물 간 이동 시간
```

| 조건 | 표시 |
|---|---|
| 공백 < 0 | 수업 시간 중복 |
| 공백 ≥ 0, 여유 < 0 | 이동 시간 부족 |
| 여유 = 0 | 여유 없음 · 여유 0분 |
| 여유 > 0 | 이동 가능 |

중복 여부를 먼저 판단하며, 가장 빠듯한 구간은 선택한 요일의 실제 여유 시간이 가장 작은 구간입니다. 등록·수정·삭제한 즉시 같은 계산 함수를 사용해 결과를 갱신합니다.

### 저장

키는 `campus-transfer-check:v1`이며 다음 구조를 사용합니다.

```json
{
  "version": 1,
  "classes": [
    {
      "id": "sample-1",
      "name": "자료구조",
      "day": "mon",
      "start": "09:00",
      "end": "10:15",
      "building": "A"
    }
  ]
}
```

- 키가 없을 때만 예시를 한 번 저장합니다. `classes: []`도 유효한 저장 상태로 취급합니다.
- JSON 또는 스키마가 잘못되면 빈 시간표와 안내를 표시하고 원본을 자동 덮어쓰지 않습니다. 이후 수업을 저장하면 새 데이터로 교체합니다.
- 일부 수업이 잘못되면 해당 항목과 중복 ID를 제외한 유효한 수업을 표시하고 안내합니다.
- 저장에 실패하면 완료 화면으로 이동하지 않고 입력값과 기존 데이터를 유지합니다. 삭제 저장에 실패해도 기존 수업을 유지합니다.
- 수업명은 HTML로 실행되지 않도록 이스케이프해서 출력합니다.

## AI를 활용한 제작 과정

1. 요구사항을 화면, 데이터, 계산, 저장, 제출 기준으로 나누어 구현 순서를 정했습니다.
2. AI를 활용해 아이보리·흰색 배경, 파란 강조색, 코랄 경고색의 UI와 로컬 SVG 아이콘·가상 안내도를 제작했습니다.
3. 화면 코드와 계산·저장 코드를 분리해 실제 수업 CRUD와 자동 저장을 구현했습니다.
4. 제공된 가상 예시를 기준으로 계산 결과를 대조하고, 자동 테스트로 입력 오류·중복·빈 저장 상태를 검증했습니다.
5. 실제 Chrome에서 모바일·PC 화면과 키보드 이동을 확인했습니다. 본문 바로가기의 해시 충돌, 보조 문구 대비, 접근 가능한 버튼 이름을 수정하고 재검증했습니다.
6. 공개 배포용 하위 경로를 로컬에서 재현해 정적 자원과 기능을 확인하고 제출 문서를 작성했습니다.


## 테스트 결과

2026-10-16 검증: **단위 테스트 19개 통과 / Chrome 브라우저 테스트 20개 통과**.

브라우저 테스트는 320·390·768·1440px 너비에서 수행했습니다. 최종 브라우저 테스트 전체를 GitHub Pages와 같은 `/campus-transfer-check/` 하위 경로에서 통과했습니다. 모바일·PC의 각 세 화면에서 axe의 WCAG A/AA 자동 검사도 통과했습니다.

[15개 요구 테스트 항목, 계산값, 환경 및 미검증 범위](docs/TESTING.md)

### 테스트 재실행

Node.js 20 이상, npm, Python 3가 필요합니다. 패키지는 테스트할 때만 설치합니다.

```sh
npm ci
npm test
npm run test:browser
```

브라우저 테스트는 설치된 Google Chrome을 사용하고 로컬 정적 서버를 자동으로 시작·종료합니다. 4173 포트를 다른 서버가 사용하고 있다면 먼저 종료합니다.

Chrome이 없다면 Playwright Chromium으로 실행할 수 있습니다.

```sh
npx playwright install chromium
PLAYWRIGHT_CHANNEL=chromium npm run test:browser
```

이미 실행 중인 정적 서버나 하위 경로를 검사할 때는 주소 끝에 `/`를 붙여 지정합니다.

```sh
PLAYWRIGHT_BASE_URL=http://127.0.0.1:4174/campus-transfer-check/ npm run test:browser
```

테스트는 격리된 브라우저를 사용하며, 실패 시 `test-results/`에 캡처와 추적 자료를 만듭니다. 자동 접근성 검사만으로 모든 사용자의 접근성을 보장하지는 않습니다. 실제 모바일 기기, Safari·Firefox 및 공개 배포 환경은 미검증입니다.

## GitHub Pages 배포 방법

1. 사용자 확인 후 공개 GitHub 저장소를 준비합니다.
2. 프로젝트 루트의 `index.html`, `css/`, `js/`, `favicon.svg`, `.nojekyll`과 제출 문서를 `main` 브랜치 루트에 올립니다. 테스트 코드도 함께 올릴 수 있지만 `node_modules/`, `test-results/`는 제외합니다.
3. 저장소의 **Settings → Pages → Build and deployment**에서 **Deploy from a branch**를 선택합니다.
4. 브랜치를 **main**, 폴더를 **/(root)**로 선택하고 저장합니다. 빌드 명령이나 별도 워크플로는 필요하지 않습니다.
5. GitHub에 표시된 배포 완료 주소를 열어 수업 저장·새로 고침을 확인합니다.

모든 자원 경로가 상대 경로이며 화면 전환은 해시를 사용합니다. 저장소 이름이 포함된 Pages 하위 경로에서도 새로 고침과 화면 이동을 지원합니다.

공식 참고: [GitHub Pages 사이트 만들기](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site), [Playwright 접근성 검사](https://playwright.dev/docs/accessibility-testing).
